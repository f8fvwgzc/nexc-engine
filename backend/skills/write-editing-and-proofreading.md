## When to use
Improving any draft before release, from reorganising a report to proofreading a final deck, and enforcing one house style across several authors.

## The four passes
Work in this order; never proofread text that will still be restructured.
| Pass | Question | Typical actions |
|---|---|---|
| Structural (developmental) | Does the whole work for its purpose and reader? | reorder, cut or add sections, close argument gaps, fix heading hierarchy, move detail to annexes |
| Line edit | Does each paragraph and sentence read well? | tighten, fix transitions, active voice, remove redundancy and jargon, keep the author's voice |
| Copyedit | Is it correct and consistent? | grammar, usage, spelling, punctuation, capitals, numbers, abbreviations, cross-references, citations, terminology |
| Proofread | Is the rendered final free of errors? | typos, dropped words, layout, numbering, captions, headers, contents, links; compare with the previous version |

## Style guides (choose one and record it)
- Chicago Manual of Style, 18th ed. (2024): books and long-form. Renames headline style to "title case" (8.159), accepts singular "they" for an unknown person (5.51), no longer requires the place of publication in book citations (14.30), prefers shortened notes to "ibid." (13.37).
- AP Stylebook, 2026-2028 edition (on sale July 2026): news and PR. No serial comma in a simple series; spell out one to nine, numerals from 10.
- Microsoft Writing Style Guide: software and UI. Sentence-case headings, contractions, serial comma, no end punctuation on headings, statements that start with a verb.
- Google developer documentation style guide: developer docs. Second person, active voice, sentence case, serial comma, code font for code, bold for UI elements.
House style overrides the base guide; the document's consistency sheet overrides both.

## Consistency sheet
Build it during the copyedit and recheck every entry at the end: US or UK spelling; exact form of terms (email, log in as verb versus login as noun); product and job-title capitals; hyphenation choices; number style (numeral threshold, % or percent, thousands separator); date and time format; abbreviations and where each is defined; list punctuation; heading case; citation style.

## Method
1. Read once without editing; note purpose, reader and the three biggest problems.
2. Agree the level of edit with the owner; structural changes need author approval.
3. Edit with tracked changes or a diff, one pass per level; use search for sheet items (every "%", every date).
4. When meaning is unclear, do not guess: add an author query ("AQ: is 2.4 m the 2025 or 2026 figure?").
5. Proofread the rendered output (PDF, page, docx), not the source. Check numbers and names twice; read headings, captions and tables separately from body text.

## Output
The edited text or diff, then: level of edit done, style guide used, the consistency sheet, author queries, and any substantive change that could alter meaning.

## Pitfalls
- Rewriting the author's voice during a copyedit, or changing technical meaning while simplifying.
- New errors introduced by edits: reread every changed sentence.
- Mixing two style guides, or fixing one instance of an error but not the others.
- Proofreading only in the editor view, where line breaks, numbering and links look different from the final file.
